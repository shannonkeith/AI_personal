## Repository Overview

This is a personal knowledge management repository organized as a collection of digital employee personas and AI-related research. The repository functions as a structured knowledge base where Keith builds expertise across multiple domains and documents insights from AI-related content and projects.

## Directory Structure

### Core Directories (1_Analyst, 2_Communication, 3_Operations, 4_Planner)

Four role-based knowledge directories representing distinct professional personas:

- **1_Analyst** - Research and data analysis capabilities. Focus: collecting, processing, and interpreting data.
- **2_Communication** - Writing and strategic communication expertise. Focus: clarity, multiple formats, storytelling structure.
- **3_Operations** - Operational management and execution.
- **4_Planner** - Planning and strategic thinking.

**Structure within each role directory:**
- `Content.md` - Core knowledge and methodology for that role
- `GEMINI.md` - Identity and rules for Gemini AI interactions (separate from Claude guidance)
- `REFERENCES.md` - External references and sources for that domain
- Additional subdirectories as needed (e.g., 2_Communication has Daily_Notes, Meeting Notes, Reference folders)

Each role directory also contains its own `CLAUDE.md` if domain-specific guidance is needed.

### AI Podcast Directory

Structured research on AI enterprise adoption, AI-native teams, and strategic technology insights. Contains:

- Episode transcripts and summaries (organized by episode or series name)
- Overview of key concepts, tools, and platforms discussed
- Context for enterprise AI adoption patterns

**See `AI podcast/CLAUDE.md`** for detailed guidance on managing podcast content.

### Project Directory

Contains project-specific materials: meeting notes, interview summaries, and presentations. Minimal structure—files added as needed.

## Content Workflow

### Adding Content to Role Directories

When documenting new expertise or updating knowledge in a role directory:

1. Update or create `Content.md` with the methodology, key principles, or knowledge
2. Add relevant external sources to `REFERENCES.md`
3. For AI-specific guidance, document in corresponding `GEMINI.md` (if different from Claude guidance)

### Adding Podcast Episodes

See `AI podcast/CLAUDE.md` for the complete workflow. Summary:
- Create transcript file with full content
- Create summary file (1/5 to 1/10 length of transcript) with guest info, key insights, and takeaways
- Document referenced tools and platforms for future context

### Adding Project Materials

Project materials are added to the `Project/` directory with minimal structure. Organize by meeting date or project name as appropriate. Meeting notes should capture decisions and key takeaways, not full transcripts.

## Key Principles

- **Clarity over perfection** - Documentation should be clear and scannable, using headers and bullet points
- **Source of truth** - Original transcripts are authoritative for exact quotes and details; summaries serve as quick reference
- **Context preservation** - Always note why knowledge matters and how it connects to broader goals
- **Cross-domain thinking** - The four personas are complementary; look for patterns that span multiple roles

## Interaction Guidance

When working in this repository:

- Treat each role directory as a distinct knowledge domain with its own standards and focus
- Use the existing CLAUDE.md files in subdirectories as the source of truth for domain-specific guidance
- When adding new content, follow the established structure and naming conventions in that directory
- Ask clarifying questions if the intent or context of a file is unclear
- Flag inconsistencies between related content across different role directories
